Sequences and lookups

Hashing and counting

Trade memory for constant-time lookup of what you have already seen.

Recognition signals
  • Find a pair or complement in unsorted input
  • Have I seen this before?
  • Count occurrences, find duplicates or the majority
  • Group items that are equivalent
  • O(n) required and sorting is not allowed
VariantHow it worksTimeSpaceUse it for
Complement lookupStore seen values, check for target minus currentO(n)O(n)Pair sums and differences on unsorted input
Frequency countingCounter or array of 26 for lettersO(n)O(k) distinctAnagrams, majority, first unique, top-K prep
Canonical key groupingMap each item to a normalized key (sorted chars, count tuple, pattern)O(n · m log m) or O(n · m)O(n · m)Group anagrams, isomorphic strings, shifted strings
Set membershipDedupe, or scan only from sequence startsO(n)O(n)Longest consecutive sequence, contains duplicate
Value to index + arraySwap the removed element with the last, update its indexO(1) average per opO(n)Insert, delete, and get random in O(1)
Template
def two_sum(nums, target):
    index = {}                      # value -> index seen so far
    for i, x in enumerate(nums):
        if target - x in index:     # check before insert: no self-pairing
            return index[target - x], i
        index[x] = i
    return None

def group_anagrams(words):
    groups = defaultdict(list)
    for w in words:
        groups[tuple(sorted(w))].append(w)   # canonical key
    return list(groups.values())
Where it goes wrong
  • Pairing an element with itself in two-sum (check before inserting)
  • Using a list as a dict key (convert to tuple)
  • Longest consecutive sequence becoming O(n²) (only start counting where x − 1 is absent)
  • Mutating a dict while iterating over it
  • Stating O(1) without the caveat (average case; adversarial collisions degrade)

In the crosswalk: Two sum, Longest consecutive sequence, Longest substring without repeating characters, Minimum window substring, Subarray sum equals K, Time-based key-value store, Top K frequent elements, LRU cache, Word ladder, Accounts merge, Task scheduler, Single number

Two pointers

Walk two indices through a sequence so each step discards candidates instead of re-checking them.

Recognition signals
  • Sorted array, or sorting is allowed
  • In place with O(1) extra space
  • Pairs or triplets meeting a condition
  • Palindromes
  • Merge or compare two sorted sequences
VariantHow it worksTimeSpaceUse it for
Opposite endslo from left, hi from right; move the side that can improveO(n)O(1)Pair sum on sorted input, container with most water, trapping rain water
Anchor + opposite endsFix one element, two-pointer the restO(n²)O(1) plus sort3Sum, 3Sum closest, 4Sum (O(n³))
Read / write pointersFast pointer scans, slow pointer writes kept itemsO(n)O(1)Remove duplicates in place, move zeros, filter
Three-way partitionlow, mid, high regions (Dutch national flag)O(n)O(1)Sort colors, partition around a pivot
Across two sequencesOne pointer per sequence, advance the smallerO(n + m)O(1)Merge sorted arrays, is-subsequence, intersections
Template
def three_sum(nums):
    nums.sort()
    out = []
    for i in range(len(nums) - 2):
        if i > 0 and nums[i] == nums[i - 1]:
            continue                          # skip duplicate anchors
        lo, hi = i + 1, len(nums) - 1
        while lo < hi:
            s = nums[i] + nums[lo] + nums[hi]
            if s < 0:
                lo += 1
            elif s > 0:
                hi -= 1
            else:
                out.append([nums[i], nums[lo], nums[hi]])
                lo += 1
                while lo < hi and nums[lo] == nums[lo - 1]:
                    lo += 1                   # skip duplicate middles
    return out
Where it goes wrong
  • Duplicate triplets in 3Sum (skip equal anchors and equal middles after a match)
  • lo < hi vs lo <= hi (can the same index be used twice?)
  • Trapping rain water: why moving the smaller side is safe (the smaller max bounds the water there)
  • Forgetting sorting costs O(n log n) and may lose original indices

In the crosswalk: Two sum, 3Sum, Trapping rain water

Sliding window

Maintain a contiguous range incrementally instead of recomputing every subarray.

Recognition signals
  • Contiguous subarray or substring
  • Longest, shortest, or at most K
  • Every window of size K
  • Counts of characters inside a range
VariantHow it worksTimeSpaceUse it for
Fixed size KAdd right; once size exceeds K, remove leftO(n)O(1) or O(alphabet)Max sum of size K, permutation in string
Variable, longest validExpand right; shrink while invalid; record after shrinkingO(n)O(alphabet)Longest substring without repeats, at most K distinct
Variable, shortest validExpand until valid; shrink while still valid, recording each timeO(n)O(alphabet)Minimum window substring, minimum size subarray sum
Exactly K via at mostcount(at most K) − count(at most K − 1)O(n)O(alphabet)Subarrays with exactly K distinct values
Window with max or minPair the window with a monotonic dequeO(n)O(K)Sliding window maximum, longest subarray with bounded range
Template
def longest_without_repeats(s):
    counts = defaultdict(int)
    best = left = 0
    for right, ch in enumerate(s):
        counts[ch] += 1
        while counts[ch] > 1:                 # invalid: shrink from left
            counts[s[left]] -= 1
            left += 1
        best = max(best, right - left + 1)    # longest: record after shrink
    return best

def shortest_with_sum_at_least(nums, target):   # non-negative nums
    best, total, left = float("inf"), 0, 0
    for right, x in enumerate(nums):
        total += x
        while total >= target:                # shortest: record while valid
            best = min(best, right - left + 1)
            total -= nums[left]
            left += 1
    return 0 if best == float("inf") else best
Where it goes wrong
  • Applying it when validity is not monotonic in window size (negative numbers break sum windows: use prefix sums)
  • Comparing whole count maps every step (track a 'satisfied' counter instead)
  • Recording the answer at the wrong moment (after shrinking for longest, during shrinking for shortest)
  • Off-by-one on window length (right − left + 1)

In the crosswalk: Longest substring without repeating characters, Minimum window substring, Sliding window maximum

Prefix sums and difference arrays

Precompute cumulative values so any range becomes a subtraction.

Recognition signals
  • Sum or count over a subarray
  • Many range queries
  • Subarray sums with negative numbers
  • Many range increments then one read
  • Product of all except self
VariantHow it worksTimeSpaceUse it for
1D prefixpre[i + 1] = pre[i] + a[i]; range sum = pre[r + 1] − pre[l]O(n) build, O(1) queryO(n)Immutable range sum
Prefix + hash mapLook up earlier prefixes equal to current − k (or same remainder mod k)O(n)O(n)Count subarrays summing to K, divisible by K, longest balanced subarray
2D prefixInclusion-exclusion over a rectangleO(mn) build, O(1) queryO(mn)Matrix region sums
Difference array+d at start, −d after end, then accumulateO(1) per update, O(n) to readO(n)Car pooling, flight bookings, range increments
Left and right passesAccumulate from both sides, combineO(n)O(1) extraProduct except self, candy distribution
Fenwick or segment treeTree over prefix ranges for interleaved updates and queriesO(log n) eachO(n)Mutable range sums, count of smaller numbers after self
Template
def count_subarrays_with_sum(nums, k):
    seen = defaultdict(int)
    seen[0] = 1                  # empty prefix
    total = count = 0
    for x in nums:
        total += x
        count += seen[total - k]
        seen[total] += 1
    return count

def apply_range_updates(n, updates):   # (start, end_inclusive, delta)
    diff = [0] * (n + 1)
    for lo, hi, d in updates:
        diff[lo] += d
        diff[hi + 1] -= d
    return list(accumulate(diff[:-1]))
Where it goes wrong
  • Forgetting to seed the map with prefix 0 (misses subarrays starting at index 0)
  • Longest subarray: store the first index of each prefix, count problems: store frequency
  • Off-by-one between length-n and length-n+1 prefix arrays
  • Choosing plain prefix sums when updates interleave with queries (use Fenwick)

In the crosswalk: Subarray sum equals K, Product of array except self, Trapping rain water

Binary search

Halve the search space using any monotonic yes/no question, not just sorted arrays.

Recognition signals
  • Sorted input
  • Minimum X such that, or maximum X such that
  • Minimize the maximum or maximize the minimum
  • O(log n) required
  • Huge answer range with a cheap feasibility check
VariantHow it worksTimeSpaceUse it for
Lower or upper boundFirst index where a[i] >= x (bisect_left) or > x (bisect_right)O(log n)O(1)First and last position, insert position, counting in ranges
On the answerSearch the value range with a monotonic feasible(x) checkO(log R · check)O(1)Ship within D days, Koko bananas, split array largest sum
Rotated or unimodalCompare mid with an endpoint to find the sorted halfO(log n)O(1)Search rotated array, find minimum, peak element
Partition two arraysBinary search a cut in the smaller arrayO(log min(m, n))O(1)Median of two sorted arrays, kth of two arrays
Over time-indexed databisect on per-key sorted timestampsO(log n) per queryO(n)Time-based key-value store, snapshot arrays
Template
def first_true(lo, hi, ok):
    """Smallest x in [lo, hi) with ok(x) True. ok is False...False True...True.
    Returns hi if no such x."""
    while lo < hi:
        mid = (lo + hi) // 2
        if ok(mid):
            hi = mid
        else:
            lo = mid + 1
    return lo

def min_eating_speed(piles, hours):          # binary search on the answer
    def ok(speed):
        return sum((p + speed - 1) // speed for p in piles) <= hours
    return first_true(1, max(piles) + 1, ok)
Where it goes wrong
  • Infinite loops from mid rounding (with lo < hi, pair hi = mid with lo = mid + 1)
  • Mixing inclusive and exclusive bounds within one search
  • Predicate that is not actually monotonic
  • Rotated arrays with duplicates degrade to O(n) worst case
  • Overflow in (lo + hi) / 2 in fixed-width languages (lo + (hi − lo) / 2)

In the crosswalk: Search in rotated sorted array, Split array largest sum, Median of two sorted arrays, Time-based key-value store, Longest increasing subsequence

Intervals, sorting, and sweep line

Sort by the right endpoint, then a single pass usually resolves overlaps.

Recognition signals
  • Intervals, meetings, bookings
  • Overlap or conflict
  • How many at the same time
  • Insert into a schedule
  • Minimum resources to cover everything
VariantHow it worksTimeSpaceUse it for
Sort by start, mergeExtend the last merged interval or start a new oneO(n log n)O(n)Merge intervals, insert interval (O(n) if pre-sorted)
Sort by end, greedy pickTake the interval that finishes firstO(n log n)O(1)Max non-overlapping, erase overlaps, minimum arrows
Sweep line events+1 at start, −1 at end, sort, running totalO(n log n)O(n)Max concurrent meetings, skyline (with a heap)
Heap of end timesPop rooms that are free before assigningO(n log n)O(n)Meeting rooms II, assigning servers or rooms
Two lists, two pointersAdvance whichever ends firstO(n + m)O(n + m)Interval list intersections, free time
Template
def merge(intervals):
    merged = []
    for start, end in sorted(intervals):
        if merged and start <= merged[-1][1]:     # closed intervals touch
            merged[-1][1] = max(merged[-1][1], end)
        else:
            merged.append([start, end])
    return merged

def max_concurrent(intervals):                    # half-open [start, end)
    events = [(s, 1) for s, _ in intervals] + [(e, -1) for _, e in intervals]
    cur = best = 0
    for _, delta in sorted(events):               # -1 sorts first on ties
        cur += delta
        best = max(best, cur)
    return best
Where it goes wrong
  • Closed vs half-open endpoints: do [1,2] and [2,3] overlap?
  • Tie ordering at equal times (process ends before starts for half-open)
  • Sorting by start when the greedy proof needs end
  • Mutating input intervals the caller still uses

In the crosswalk: 3Sum, Merge intervals, Meeting rooms II

Ordered and prioritized

Monotonic stack and deque

Keep a stack in sorted order so each element is pushed and popped once, answering nearest-greater questions in O(n).

Recognition signals
  • Next greater or smaller element
  • For each item, the nearest X to the left or right
  • Span or how many days until
  • Histogram rectangles
  • Remove characters or digits to get the smallest result
VariantHow it worksTimeSpaceUse it for
Next greater / smallerDecreasing (or increasing) stack of indices; resolve on popO(n)O(n)Daily temperatures, next greater element, stock span
Both-side boundariesPrevious and next smaller per element, then contribution countingO(n)O(n)Largest rectangle in histogram, sum of subarray minimums
Monotonic dequeDrop dominated items from the back, expired from the frontO(n)O(K)Sliding window maximum, shortest subarray with sum at least K
Greedy removal stackPop larger previous items while removal budget allowsO(n)O(n)Remove K digits, smallest subsequence of distinct characters
Parsing stackPush context, pop on closeO(n)O(n)Valid parentheses, basic calculator, decode string
Template
def next_greater(nums):
    result = [-1] * len(nums)
    stack = []                                  # indices; values decreasing
    for i, x in enumerate(nums):
        while stack and nums[stack[-1]] < x:
            result[stack.pop()] = x
        stack.append(i)
    return result

def window_max(nums, k):
    dq, out = deque(), []                       # indices; values decreasing
    for i, x in enumerate(nums):
        while dq and nums[dq[-1]] <= x:
            dq.pop()
        dq.append(i)
        if dq[0] <= i - k:
            dq.popleft()                        # fell out of the window
        if i >= k - 1:
            out.append(nums[dq[0]])
    return out
Where it goes wrong
  • Storing values when you need indices for distances or widths
  • Strict vs non-strict comparisons with duplicates (double counting in contribution sums)
  • Forgetting to flush the stack at the end (a sentinel value helps)
  • Assuming O(n²) because of the nested while (amortized O(n))

In the crosswalk: Trapping rain water, Daily temperatures, Largest rectangle in histogram, Sliding window maximum

Heaps and top-K

Always know the smallest or largest item under insertions, in O(log n).

Recognition signals
  • K largest, smallest, closest, most frequent
  • A stream of values
  • Merge K sorted inputs
  • Repeatedly take the best available option
  • Running median
VariantHow it worksTimeSpaceUse it for
Size-K min-heapPush, evict smallest when size exceeds KO(n log K)O(K)Top K from large or streaming input
QuickselectPartition around a pivot until K landsO(n) average, O(n²) worstO(1)One-off kth element on in-memory array
K-way mergeHeap holds the head of each listO(N log K)O(K)Merge K sorted lists, smallest range covering K lists
Two heapsMax-heap for lower half, min-heap for upper half, rebalanceO(log n) add, O(1) medianO(n)Median of a data stream
Lazy deletionMark removed items, discard them when they surface at the topO(log n) amortizedO(n)Sliding window median, cancellable schedulers
Greedy with heapPop best, update, push backO(n log n)O(n)Task scheduler, reorganize string, IPO, connect ropes
Template
def top_k_frequent(nums, k):
    heap = []                                   # min-heap, size <= k
    for value, count in Counter(nums).items():
        heapq.heappush(heap, (count, value))
        if len(heap) > k:
            heapq.heappop(heap)                 # evict the smallest
    return [v for _, v in heap]

def merge_k_sorted(lists):
    heap = [(lst[0], i, 0) for i, lst in enumerate(lists) if lst]
    heapq.heapify(heap)                         # (value, list id, position)
    out = []
    while heap:
        val, i, j = heapq.heappop(heap)
        out.append(val)
        if j + 1 < len(lists[i]):
            heapq.heappush(heap, (lists[i][j + 1], i, j + 1))
    return out
Where it goes wrong
  • heapq is min-only (negate values for a max-heap)
  • Tuple ties falling through to uncomparable objects (add a counter as tiebreaker)
  • heapify is O(n), not O (n log n)
  • Using a heap when K is close to n (just sort)

In the crosswalk: Meeting rooms II, Top K frequent elements, Find median from data stream, Merge K sorted lists, Network delay time, Task scheduler

Linked and hierarchical

Linked list manipulation

Rewire pointers in place, using a dummy node and pointer gaps to avoid special cases.

Recognition signals
  • Linked list input
  • In place, O(1) extra space
  • Cycle detection or its start
  • Middle node, or nth from the end
  • Reorder, reverse a section
VariantHow it worksTimeSpaceUse it for

In-place reversalprev / cur / next rewiring; for sublists reconnect both endsO(n)O(1)Reverse list, reverse between, reverse in K-groups, palindrome check

Template
def reverse(head):
    prev = None
    while head:
        nxt = head.next          # save before rewiring
        head.next = prev
        prev, head = head, nxt
    return prev

def remove_nth_from_end(head, n):
    dummy = ListNode(0, head)    # handles removing the head
    fast = slow = dummy
    for _ in range(n + 1):
        fast = fast.next         # open a gap of n nodes
    while fast:
        fast, slow = fast.next, slow.next
    slow.next = slow.next.next
    return dummy.next
Where it goes wrong
  • Losing the next pointer before rewiring
  • Leaving the old tail pointing somewhere (accidental cycle)
  • Null checks: while fast and fast.next
  • Leftover group shorter than K in K-group reversal

In the crosswalk: Merge K sorted lists, LRU cache, Reverse nodes in K-group

  • Ancestor of two nodes
  • Serialize or construct a tree
VariantHow it worksTimeSpaceUse it for
Postorder, return upwardChildren return summaries, node combines, updates a global bestO(n)O(h)Height, balanced, diameter, max path sum

def diameter(root):
    best = 0
    def height(node):                    # return value flows up
        nonlocal best
        if not node:
            return 0
        left, right = height(node.left), height(node.right)
        best = max(best, left + right)   # path through this node
        return 1 + max(left, right)      # path usable by the parent
    height(root)
    return best

def level_order(root):
    levels, q = [], deque([root] if root else [])
    while q:
        levels.append([])
        for _ in range(len(q)):          # exactly one level
            node = q.popleft()
            levels[-1].append(node.val)
            q.extend(c for c in (node.left, node.right) if c)
    return levels
Where it goes wrong
  • Recursion depth on skewed trees (Python's default limit is about 1,000; go iterative)
  • Confusing the path through a node (for the answer) with the path returned to the parent
  • Validating a BST by comparing only with the parent (pass bounds)
  • O(n²) builds from searching inorder each time (use an index map)

In the crosswalk: Binary tree maximum path sum, Lowest common ancestor, Serialize and deserialize binary tree

Tries

Share prefixes across many strings so prefix queries cost the length of the prefix.

Recognition signals
  • Prefix search or autocomplete
  • Search many words at once
  • Dictionary of words against a grid or stream
  • Longest common prefix across many strings
  • Maximum XOR of a pair
VariantHow it worksTimeSpaceUse it for
Dict-of-dicts trieNested maps with an end markerO(L) per opO(total chars)General purpose, sparse alphabets
Array childrenFixed 26-slot arrays per nodeO(L) per op, faster constantsO(26 · nodes)Lowercase letters, performance-sensitive
Trie + grid backtrackingWalk the trie while walking the board; prune found wordsO(cells · 4^L) worstO(total chars)Word search II, boggle

Template
class Trie:
    END = object()                       # sentinel: can't collide with a char

    def __init__(self):
        self.root = {}

    def insert(self, word):
        node = self.root
        for ch in word:
            node = node.setdefault(ch, {})
        node[Trie.END] = word

    def find_prefix(self, prefix):
        node = self.root
        for ch in prefix:
            if ch not in node:
                return None
            node = node[ch]
        return node

    def words_with_prefix(self, prefix):
        node, out = self.find_prefix(prefix), []
        stack = [node] if node is not None else []
        while stack:
            cur = stack.pop()
            for key, child in cur.items():
                if key is Trie.END:
                    out.append(child)
                else:
                    stack.append(child)
        return out
Where it goes wrong
  • End marker colliding with a real character (use a sentinel object or field)
  • Not pruning found words or dead branches in word search II (time limit)
  • Memory blowup with large alphabets or long keys (compressed tries)

In the crosswalk: Word search II

DIRS = ((1, 0), (-1, 0), (0, 1), (0, -1))

def multi_source_bfs(grid, sources):         # grid cells: "#" is a wall
    rows, cols = len(grid), len(grid[0])
    dist = {cell: 0 for cell in sources}
    q = deque(sources)
    while q:
        r, c = q.popleft()
        for dr, dc in DIRS:
            nr, nc = r + dr, c + dc
            if (0 <= nr < rows and 0 <= nc < cols
                    and grid[nr][nc] != "#" and (nr, nc) not in dist):
                dist[(nr, nc)] = dist[(r, c)] + 1   # mark on enqueue
                q.append((nr, nc))
    return dist

def count_components(n, edges):
    graph = defaultdict(list)
    for a, b in edges:
        graph[a].append(b)
        graph[b].append(a)
    seen, count = set(), 0
    for start in range(n):
        if start in seen:
            continue
        count += 1
        seen.add(start)
        stack = [start]
        while stack:
            for nxt in graph[stack.pop()]:
                if nxt not in seen:
                    seen.add(nxt)
                    stack.append(nxt)
    return count
Where it goes wrong
  • Marking visited on dequeue (duplicates flood the queue)
  • Missing reverse edges for undirected graphs
  • State that omits something affecting future moves
  • Recursive DFS on a 1,000 × 1,000 grid (stack overflow in Python)
  • Disconnected graphs: loop over all nodes, not just node 0

Template
def topo_order(n, edges):                  # (a, b) means a before b
    graph, indegree = defaultdict(list), [0] * n
    for a, b in edges:
        graph[a].append(b)
        indegree[b] += 1
    q = deque(i for i in range(n) if indegree[i] == 0)
    order = []
    while q:
        node = q.popleft()
        order.append(node)
        for nxt in graph[node]:
            indegree[nxt] -= 1
            if indegree[nxt] == 0:
                q.append(nxt)
    return order if len(order) == n else None  # None: cycle exists

Union-find

Template
class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n
        self.components = n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]   # path halving
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False                  # already connected: a cycle edge
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra               # union by size
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        self.components -= 1
        return True
Where it goes wrong
  • Comparing parent[x] instead of find (x)
  • Counting components without calling find on each node
  • No support for deletions (process offline in reverse)
  • Forgetting to update the component count

def dijkstra(graph, source):               # graph[u] = [(v, weight), ...]
    dist = {source: 0}
    heap = [(0, source)]
    while heap:
        d, u = heapq.heappop(heap)
        if d > dist[u]:
            continue                          # stale entry, skip
        for v, w in graph.get(u, ()):
            nd = d + w
            if nd < dist.get(v, float("inf")):
                dist[v] = nd
                heapq.heappush(heap, (nd, v))
    return dist

def cheapest_within_k_stops(n, flights, src, dst, k):
    cost = [float("inf")] * n
    cost[src] = 0
    for _ in range(k + 1):                    # k stops = k + 1 edges
        nxt = cost[:]                         # relax from last round only
        for u, v, w in flights:
            if cost[u] + w < nxt[v]:
                nxt[v] = cost[u] + w
        cost = nxt
    return -1 if cost[dst] == float("inf") else cost[dst]
Where it goes wrong
  • Processing stale heap entries (check d > dist[u])
  • Dijkstra with negative weights
  • K-stop limits: plain Dijkstra discards paths that are costlier but use fewer stops
  • Bellman-Ford rounds reading values updated in the same round

In the crosswalk: Network delay time, Cheapest flights within K stops

Backtracking

Build candidates one choice at a time, undo, and prune branches that cannot succeed.

Recognition signals

VariantHow it worksTimeSpaceUse it for
SubsetsStart index; record at every nodeO(n · 2ⁿ)O(n)Subsets, subsets with duplicates
PermutationsUsed set or in-place swapsO(n · n!)O(n)Permutations, next permutation variants
Combinations to targetStart index; reuse with i, no reuse with i + 1Exponential, prunedO(target)Combination sum I, II, III
Constraint placementSets for columns and diagonalsO(n!) prunedO(n)N-Queens, sudoku solver

PartitioningChoose a cut, validate prefix, recurse on restO(n · 2ⁿ)O(n)Palindrome partitioning, restore IP addresses
Template
def combination_sum(candidates, target):    # each number reusable
    candidates = sorted(candidates)
    result, path = [], []
    def backtrack(start, remaining):
        if remaining == 0:
            result.append(path[:])             # copy, not the live list
            return
        for i in range(start, len(candidates)):
            if candidates[i] > remaining:
                break                          # sorted: prune the rest
            path.append(candidates[i])
            backtrack(i, remaining - candidates[i])   # i + 1 if no reuse
            path.pop()                         # undo
    backtrack(0, target)
    return result

def subsets_with_dups(nums):
    nums = sorted(nums)
    result, path = [], []
    def backtrack(start):
        result.append(path[:])
        for i in range(start, len(nums)):
            if i > start and nums[i] == nums[i - 1]:
                continue                       # skip duplicate branch
            path.append(nums[i])
            backtrack(i + 1)
            path.pop()
    backtrack(0)
    return result
Where it goes wrong
  • Appending the live path instead of a copy
  • Forgetting to undo state after the recursive call
  • Duplicate results with repeated values (sort, skip i > start with equal neighbor)
  • Weak pruning (sort candidates so you can break early)

In the crosswalk: Word search II, N-Queens

def coin_change(coins, amount):              # unbounded knapsack
    INF = float("inf")
    best = [0] + [INF] * amount
    for a in range(1, amount + 1):
        for c in coins:
            if c <= a and best[a - c] + 1 < best[a]:
                best[a] = best[a - c] + 1
    return -1 if best[amount] == INF else best[amount]

def edit_distance(a, b):                     # two sequences, rolling row
    prev = list(range(len(b) + 1))
    for i in range(1, len(a) + 1):
        cur = [i] + [0] * len(b)
        for j in range(1, len(b) + 1):
            if a[i - 1] == b[j - 1]:
                cur[j] = prev[j - 1]
            else:
                cur[j] = 1 + min(prev[j], cur[j - 1], prev[j - 1])
        prev = cur
    return prev[-1]

def lis_length(nums):                        # O(n log n) patience sorting
    tails = []
    for x in nums:
        i = bisect_left(tails, x)
        if i == len(tails):
            tails.append(x)
        else:
            tails[i] = x
    return len(tails)

  • 0/1 knapsack iterating capacity upward (reuses an item)
  • Missing base cases, or initializing min problems with 0 instead of infinity
  • Memoizing on mutable or unhashable arguments

def max_non_overlapping(intervals):          # sort by END, not start
    count, last_end = 0, float("-inf")
    for start, end in sorted(intervals, key=lambda iv: iv[1]):

    return count

def min_jumps(jumps):                        # BFS in layers, O(n)
    steps = cur_end = farthest = 0
    for i in range(len(jumps) - 1):
        farthest = max(farthest, i + jumps[i])
        if i == cur_end:                      # layer exhausted: jump
            steps += 1
            cur_end = farthest
    return steps

Code review and debugging

Some companies hand you a working but flawed pull request or a failing program. These are the categories of defects they plant.

Correctness bugs
Off-by-one errors, unhandled empty input, mutating a collection while iterating, mutable default arguments, integer division.
Concurrency defects
Check-then-act races, shared state without synchronization, holding locks across I/O, deadlock-prone lock ordering.
Resource handling
Unclosed files and connections, missing timeouts, unbounded caches or queues, retries without backoff.
Performance regressions
Nested loops over large inputs, N+1 queries, repeated string concatenation, recomputation that could be cached.
Error handling
Swallowed exceptions, errors without context, partial failure leaving inconsistent state.
API and structure
Unclear naming, leaky abstractions, functions doing several jobs, hard-to-test code with hidden dependencies such as the clock.
